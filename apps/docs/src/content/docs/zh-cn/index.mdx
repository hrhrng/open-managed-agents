## openma 是什么？

**openma**（Open Managed Agents）是 AI agent 的基础设施层。你带来 Harness——决定模型下一步做什么的循环——openma 负责其余的一切：持久 Session、沙箱中的代码执行、工具调用、语义记忆、隔离安全的凭据，以及崩溃恢复。

它完全运行在 Cloudflare（Workers、Durable Objects、D1、R2、KV、Vectorize、Containers）上。你可以**使用 [openma.dev](https://app.openma.dev) 上的托管产品**，也可以 **fork 并自托管**到自己的 Cloudflare 账号。

## 为什么选择 openma？

大多数 agent 框架告诉你*如何*构建一个 agent——循环、提示词格式、编排形态。openma 不同：它不介入 Harness，而是提供每个长时间运行的 agent 都需要、自己做起来却很痛苦的东西。

<CardGrid>
  <Card title="持久 Session" icon="approve-check">
    每个 Session 在由 SQLite 支撑的 Durable Object 里保存只追加的事件日志。可以从任意位置恢复；能经受重启和崩溃。
  </Card>
  <Card title="沙箱执行" icon="seti:docker">
    工具调用在按 Session 划分的 Cloudflare Containers 中运行。用声明式方式预装 Python / Node / apt 包。
  </Card>
  <Card title="由 Vault 支撑的凭据" icon="seti:lock">
    凭据永远不会进入沙箱。出站代理按主机注入认证头，于是工具可以访问私有 API，却始终看不到密钥。
  </Card>
  <Card title="内置记忆" icon="document">
    跨 Session 的、按 Agent 划分的语义记忆，通过 Workers AI embeddings 索引在 Vectorize 中。
  </Card>
  <Card title="无处不在的 MCP" icon="puzzle">
    连接任意 MCP 服务器，openma 会自动生成模型可以调用的 `mcp_*` 工具。
  </Card>
  <Card title="第一天就有的三项集成" icon="rocket">
    把 Agent 发布到 Linear（可指派的 issue）、GitHub（PR）和 Slack（频道），认证由 OAuth 管理。
  </Card>
</CardGrid>
